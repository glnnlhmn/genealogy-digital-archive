## 1. Operator Reference & Quick-Start

### Operational Intent
`install_hooks.py` deploys, audits, and removes automated client-side Git quality gates for the repository. It installs two POSIX/Git Bash shell hook scripts into `.git/hooks/`:
* **`pre-commit`:** Executes `pytest -m smoke -q` to block commits if in-memory smoke assertions fail (< 5s).
* **`pre-push`:** Executes `pytest -q` to block pushes to remote branches if regressions exist across the full test suite.

### CLI Syntax
```powershell
python tools/sys/install_hooks.py [--status] [--uninstall]
```

### Options & Parameter Reference
* `(no args)`: Installs or overwrites both `pre-commit` and `pre-push` hook files and applies POSIX executable permissions.
* `--status`: Inspects `.git/hooks/` and displays the installation state of both hooks without modifying the filesystem.
* `--uninstall`: Deletes `pre-commit` and `pre-push` from `.git/hooks/` if present.

### Quick Runbook


#### Install Automated Hooks


#### Uninstall Automated Hooks

## 2. Technical Architecture & Hook Lifecycles

### Hook Script Architecture

#### 1. Pre-Commit Hook (`.git/hooks/pre-commit`)
```sh
#!/bin/sh
# Auto-generated by tools/sys/install_hooks.py
echo "[GIT-HOOK] Running pre-commit smoke tests (-m smoke)..."

python -m pytest -m smoke -q
RESULT=$?

# Exit code 0 = passed; Exit code 5 = zero tests collected matching marker
if [ $RESULT -ne 0 ] && [ $RESULT -ne 5 ]; then
    echo ""
    echo "======================================================================="
    echo "[HOOK BLOCKED] Smoke tests failed. Commit aborted."
    echo "Fix failing assertions or run 'python -m pytest -m smoke' to diagnose."
    echo "======================================================================="
    exit 1
fi

echo "[GIT-HOOK] Smoke tests passed cleanly. Proceeding with commit."
exit 0
```
* **Exit Code Handling:** Allows return code `0` (passed) and code `5` (pytest standard return when no tests match the marker). Any test failure aborts `git commit`.

#### 2. Pre-Push Hook (`.git/hooks/pre-push`)
```sh
#!/bin/sh
# Auto-generated by tools/sys/install_hooks.py
echo "[GIT-HOOK] Running comprehensive test suite prior to remote push..."

python -m pytest -q
RESULT=$?

if [ $RESULT -ne 0 ]; then
    echo ""
    echo "======================================================================="
    echo "[HOOK BLOCKED] Test suite failed. Push to remote rejected."
    echo "Run 'python -m pytest' locally to inspect and fix all regressions."
    echo "======================================================================="
    exit 1
fi

echo "[GIT-HOOK] Comprehensive test suite passed. Pushing to remote."
exit 0
```

### Permissions Enforcement
The installer resolves file permissions using Python's `stat` module, adding user, group, and other execute bits (`stat.S_IXUSR | stat.S_IXGRP | stat.S_IXOTH`) to ensure execution compatibility across Git Bash and Windows POSIX emulators.

## 3. Verification Harness & Diagnostics

### Test Suite
* **Location:** `tests/unit/test_install_hooks.py`
* **Test Isolation:** Exercises hook writing, permission setting, status reporting, and uninstallation inside hermetic `tmp_path` sandboxes with zero live repository mutation.
* **Execution:**
```powershell
pytest tests/unit/test_install_hooks.py -v
```

### Diagnostic Matrix
* **Error (`Git directory not found at: ...`):** Script executed outside a valid Git clone or `.git` folder is missing. Ensure command is run within the repository workspace.
* **Hook Blocked (`[HOOK BLOCKED] Smoke tests failed`):** A fast smoke assertion failed during commit. Run `pytest -m smoke -v` locally to identify and remediate the regression.
* **Hook Blocked (`[HOOK BLOCKED] Test suite failed`):** Unit, integration, or regression tests failed during push. Run `pytest -v` to isolate failing tests before pushing upstream.
